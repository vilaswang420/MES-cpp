## 1. 概述与架构

### 1.1 适用场景

本手册面向使用手持 PAD（工业平板/PDA）在车间现场作业的人员，覆盖以下典型场景:

| 角色 | 场景 | 核心操作 |
|------|------|---------|
| 车间操作员 | 接单 → 生产 → 报工 | 扫工单二维码 → 查看工序 → 扫码报工 |
| 质检员 | 首件/过程/完工检验 | 扫工单 → 录入检验数据 → 记录缺陷 |
| 仓库管理员 | 领料/入库 | 扫物料码 → 核对数量 → 确认领用/入库 |
| 班组长 | 工单管理 | 扫码开工/暂停/完工 → 查看进度 |

### 1.2 系统架构

```
┌─────────────────────────────────────────────────┐
│              手持 PAD (PWA / 轻量 App)             │
│                                                   │
│  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐         │
│  │扫码   │  │工单   │  │报工   │  │质检   │         │
│  │Camera │  │详情   │  │录入   │  │录入   │         │
│  └──┬───┘  └──┬───┘  └──┬───┘  └──┬───┘         │
│     │         │         │         │              │
│     └─────────┴─────────┴─────────┘              │
│                    │ HTTPS                        │
└────────────────────┼────────────────────────────┘
                     │
              ┌──────▼──────┐
              │   Nginx     │ :443 TLS
              │   (入口)    │
              └──────┬──────┘
                     │
              ┌──────▼──────┐
              │  MES 后端    │ REST API
              │  (Drogon)   │ + WebSocket
              └──────┬──────┘
                     │
         ┌───────────┼───────────┐
         │           │           │
    ┌────▼───┐ ┌────▼───┐ ┌────▼───┐
    │PostgreSQL│ │ Redis  │ │RabbitMQ│
    │  (数据)  │ │(缓存)  │ │ (MQ)   │
    └────────┘ └────────┘ └────────┘
```

**关键设计**: PAD 通过 HTTPS REST API 与后端通信, 复用现有 76 条路由, 无需额外后端开发。扫码功能由 PAD 浏览器原生 Camera API 或外接蓝牙扫码枪实现。

### 1.3 二维码规范

MES 系统中使用的二维码统一遵循以下编码规则:

| 二维码类型 | 编码格式 | 示例 | 扫码后行为 |
|-----------|---------|------|-----------|
| 工单码 | `MES:WO:{work_order_id}` | `MES:WO:50` | 跳转工单详情页 |
| 工序码 | `MES:OP:{operation_id}` | `MES:OP:101` | 跳转报工页面 |
| 物料码 | `MES:MAT:{material_code}` | `MES:MAT:MAT-A001` | 跳转领料核对页 |
| 设备码 | `MES:DEV:{device_id}` | `MES:DEV:10` | 跳转设备状态页 |
| 产品序列码 | `MES:SN:{serial_no}` | `MES:SN:SN20260815-001` | 追溯查询 |

> 工单二维码可在管理后台工单详情页生成 (未来实现), 或由系统在工单下达时自动打印。

## 2. PAD 硬件与环境要求

### 2.1 PAD 硬件推荐

| 项目 | 最低要求 | 推荐 |
|------|---------|------|
| 屏幕 | 5 英寸以上, 分辨率 720p+ | 8 英寸, 1080p |
| 操作系统 | Android 10+ / iOS 14+ | Android 13+ |
| 摄像头 | 有 (用于扫码) | 支持自动对焦 |
| 扫码方式 | 摄像头扫码 | 蓝牙扫码枪 (效率更高) |
| 网络 | Wi-Fi 2.4GHz | Wi-Fi 5GHz |
| 防护等级 | — | IP65 (车间防尘防水) |
| 电池 | — | ≥ 4000mAh (支持一班次) |

### 2.2 软件环境

PAD 只需安装浏览器 (Chrome / Edge), 无需安装 App。系统通过 PWA (Progressive Web App) 方式提供:

1. 在浏览器中访问 MES 系统地址: `https://mes.yourcompany.com/pad/`
2. 登录后浏览器会提示 "添加到主屏幕"
3. 点击添加后, PAD 桌面出现 MES 图标, 以后点击即可全屏启动

### 2.3 网络要求

- PAD 需连接车间 Wi-Fi, 能访问 MES 服务器 (443 端口)
- 网络延迟建议 < 100ms (扫码后页面跳转流畅)
- 断网时 PAD 会提示 "网络不可用", 恢复后自动重连

## 4. 工单扫码接入

### 4.1 扫码进入工单

**场景**: 操作员在工位拿到工单打印件 (含二维码), 扫码快速进入工单详情。

**操作步骤**:

1. 在首页点击 "扫码作业"
2. PAD 摄像头开启, 将二维码对准取景框
3. 识别成功后, 系统根据二维码类型自动跳转:

   - 工序码 `MES:OP:101` → 跳转报工页面

### 4.3 手动查询工单

如无二维码, 可手动输入工单号:

1. 首页 → "工单管理" → 搜索框
2. 输入工单号 (如 `WO20260815001`)
3. 或按状态筛选 (待排产/已下达/进行中/已完工)
4. 点击工单进入详情

### 4.4 工单状态操作

班组长 (有权限的角色) 可在工单详情页执行状态流转:

| 操作 | 权限码 | 前置状态 | 目标状态 | 说明 |
|------|--------|---------|---------|------|
| 排产 | prod:wo:schedule | 0:待排产 | 1:已排产 | 指定产线/计划时间 |
| 下达 | prod:wo:release | 1:已排产 | 2:已下达 | 通知产线准备 |
| 开工 | prod:wo:start | 2:已下达 | 3:进行中 | 开始生产, 触发采集 |
| 暂停 | prod:wo:pause | 3:进行中 | 4:已暂停 | 暂停生产 |
| 完工 | prod:wo:complete | 3:进行中 | 5:已完工 | 手动完工 (满量自动完工) |
| 关闭 | prod:wo:close | 5:已完工 | 6:已关闭 | 归档 |

## 5. 工序报工操作

### 5.1 报工流程

```
扫码/选择工单 → 选择工序 → 录入报工数据 → 提交
                                    │
                              ┌─────▼─────┐
                              │ 后端校验   │
                              │ (并发防护) │
                              └─────┬─────┘
                                    │
                         ┌──────────┼──────────┐
                         │          │          │
                    ✅ 成功    ⚠️ 超报    ❌ 无权限
                    返回详情    409 拒绝    403 拒绝
```

### 5.2 报工操作步骤

1. 在工单详情页, 点击当前进行中工序的 "📋 报工" 按钮
2. 进入报工录入页面:

```
┌─────────────────────────────┐
│  ← 返回    工序报工          │
├─────────────────────────────┤
│                              │
│  工单: WO20260815001         │
│  工序: 3-精加工              │
│  工位: WS-005 (1号线)        │
│  操作员: 张三 (ID: 88)       │
│                              │
│  ┌────────────────────────┐ │
│  │  完成数量:    100       │ │  ← 必填
│  └────────────────────────┘ │
│  ┌────────────────────────┐ │
│  │  合格数量:     95       │ │  ← 必填
│  └────────────────────────┘ │
│  ┌────────────────────────┐ │
│  │  不良数量:      5       │ │  ← 自动计算 = 完成 - 合格
│  └────────────────────────┘ │
│  ┌────────────────────────┐ │
│  │  班次:  早班 ▼          │ │  ← 1:早班 2:中班 3:夜班
│  └────────────────────────┘ │
│  ┌────────────────────────┐ │
│  │  备注:  首件合格...     │ │  ← 可选
│  └────────────────────────┘ │
│                              │
│  ┌────────────────────────┐ │
│  │       ✅ 提交报工       │ │
│  └────────────────────────┘ │
│                              │
└─────────────────────────────┘
```

3. 填写完成数量和合格数量
4. 不良数量自动计算 (完成 - 合格), 也可手动修改
5. 选择班次
6. (可选) 填写备注
7. 点击 "提交报工"

### 5.3 报工结果处理

| 结果 | 提示 | 后续操作 |
|------|------|---------|
| ✅ 成功 | "报工成功, 工单进度 58% → 68%" | 返回工单详情或继续报工 |
| ⚠️ 超报 | "报工失败: 已超出计划数量" | 检查完成数量是否正确 |
| ❌ 超报冲突 | "报工冲突: 其他操作员已报工, 请刷新后重试" | 刷新工单详情, 查看最新进度 |
| ❌ 无权限 | "无权限: 需要 prod:wo:report 权限" | 联系管理员分配权限 |
| ❌ 工单非进行中 | "工单状态不允许报工" | 检查工单是否已开工 |

### 5.4 并发报工说明

- 多个操作员同时对同一工单报工时, 系统使用行级锁 (`SELECT ... FOR UPDATE`) 串行化处理
- 报工数量 + 已完成数量 > 计划数量 时, 报工被拒绝 (409 Conflict)
- 最后一件报工成功后, 工单自动完工 (status → 5), 并自动发送停采指令

### 5.5 扫码报工快捷流程

针对高频报工场景, PAD 支持快捷流程:

1. 首页 → "扫码作业"
2. 扫描工序码 `MES:OP:101` → 直接进入报工页面 (跳过工单详情)
3. 录入数量 → 提交 → 自动返回扫码页面 (准备下一次扫码)

## 6. 物料领用与核对

```
仓库管理员扫物料码 → 核对物料信息 → 确认领用 → WMS 同步
```

2. 或直接扫物料码 `MES:MAT:MAT-A001`

### 6.3 领料结果

```
│                              │
│  ┌──────────┐ ┌──────────┐  │
│  │ +添加缺陷 │ │ ✅ 提交   │  │
│  └──────────┘ └──────────┘  │
│                              │
└─────────────────────────────┘
```

3. 选择检验类型 (首件/过程/完工/抽样)
4. 逐项录入实测值, 系统自动判断合格/超差
5. 如有不良, 填写缺陷记录 (类型/严重度/处置方式)
6. 可添加多条缺陷记录
7. 点击 "提交"

### 7.3 检验结果

- 合格 (result=1): 工单可继续生产
- 不合格 (result=2): 需记录缺陷并处置 (返工/返修/报废/让步)
- 让步接收 (result=3): 需上级审批

### 7.4 缺陷处置

| 处置方式 | 代码 | 说明 |
|---------|------|------|
| 返工 | 1 | 重新加工使其合格 |
| 返修 | 2 | 修复缺陷, 可能不完全合格 |
| 报废 | 3 | 无法修复, 作废处理 |
| 让步 | 4 | 不完全合格但客户接受 |

## 11. 故障排除

### 11.1 常见问题

| 问题 | 可能原因 | 解决方案 |
|------|---------|---------|
| 无法登录 | 用户名/密码错误, 或账号已禁用 | 检查输入; 联系管理员启用账号 |
| 扫码无反应 | 摄像头权限未授予, 或二维码模糊 | 在 PAD 设置中授予浏览器摄像头权限; 清洁摄像头; 调整距离 |
| 页面加载慢 | 网络信号弱 | 移动到 Wi-Fi 信号强的区域; 检查车间 AP 覆盖 |
| 报工失败 "超报" | 报工数量超出计划, 或其他操作员已报工 | 刷新工单详情查看最新进度; 核对剩余可报数量 |
| 报工失败 "冲突" | 其他操作员同时报工 | 自动重试或等待几秒后重试 |
| WMS 领料失败 | WMS 服务不可用或库存不足 | 系统自动重试; 联系仓库确认库存 |
| 告警未推送 | WS 连接断开 | 检查底栏连接状态; 系统会自动切 REST 轮询 |
| 提示 "无权限" | 角色未分配对应权限 | 联系管理员分配权限 |
| 工单无法开工 | 工单状态非 "已下达" | 联系班组长先执行 "下达" 操作 |
| 页面白屏 | 浏览器缓存问题 | 清除浏览器缓存; 或在地址栏加 `?v=2` 刷新 |

### 11.2 网络断开时的行为

- **已打开的页面**: 可继续查看已加载的数据, 但无法提交操作
- **报工操作**: 提交会失败, 提示 "网络不可用", 数据不会丢失 (需重新提交)
- **告警推送**: WS 断开, 系统自动切 REST 轮询 (10s 间隔), 网络恢复后自动回切
- **恢复连接**: 底栏指示灯从红色变绿色, 可正常操作

|---------|--------|
| 账号/权限问题 | 系统管理员 |
| 工单/排产问题 | 生产主管 |

### 12.3 扫码实现

**方案 A: 浏览器 Camera API (PWA)**

```typescript
// 使用 getUserMedia + BarcodeDetector API (Chrome/Edge 支持)
async function startScanning(videoRef: HTMLVideoElement) {
    const stream = await navigator.mediaDevices.getUserMedia({
        video: { facingMode: 'environment' }  // 后置摄像头
    });
    videoRef.srcObject = stream;

    const detector = new BarcodeDetector({
        formats: ['qr_code', 'code_128', 'code_39', 'ean_13']
    });

    const scan = async () => {
        const barcodes = await detector.detect(videoRef);
        if (barcodes.length > 0) {
            const code = barcodes[0].rawValue;
            handleScanResult(code);  // 解析 MES:WO:50 格式
        }
        requestAnimationFrame(scan);
    };
    scan();
}
```

**方案 B: 蓝牙扫码枪**

蓝牙扫码枪作为键盘输入设备, 扫码后自动输入文本 + 回车:

```typescript
// 监听键盘输入, 扫码枪输入速度远快于手动打字
let scanBuffer = '';
let scanTimer: number;

document.addEventListener('keydown', (e) => {
    scanBuffer += e.key;
    clearTimeout(scanTimer);
    scanTimer = setTimeout(() => {
        if (scanBuffer.startsWith('MES:')) {
            handleScanResult(scanBuffer);
        }
        scanBuffer = '';
    }, 50);  // 扫码枪输入间隔 < 50ms
});
```

### 12.4 二维码解析

```typescript
function handleScanResult(code: string) {
    // 格式: MES:{TYPE}:{ID}
    const match = code.match(/^MES:(\w+):(.+)$/);
    if (!match) {
        message.error('无效的二维码格式');
        return;
    }

    const [, type, id] = match;
    switch (type) {
        case 'WO':
            navigate(`/pad/work-orders/${id}`);
            break;
        case 'OP':
            navigate(`/pad/report?operation_id=${id}`);
            break;
        case 'MAT':
            navigate(`/pad/material-pick?material_code=${id}`);
            break;
        case 'DEV':
            navigate(`/pad/devices/${id}`);
            break;
        case 'SN':
            navigate(`/pad/stock-in?serial_no=${id}`);
            break;
        default:
            message.error('未知的二维码类型');
    }
}
```

### 12.7 离线缓存 (PWA Service Worker)

```typescript
// 可选: 缓存 PAD 核心页面, 断网时仍可查看已加载工单
const CACHE_NAME = 'mes-pad-v1';
const CACHE_URLS = [
    '/pad/',
    '/pad/index.html',
    '/pad/manifest.json',
];

self.addEventListener('install', (event) => {
    event.waitUntil(
        caches.open(CACHE_NAME).then(cache => cache.addAll(CACHE_URLS))
    );
});
```

### 12.8 PAD 端 UI 设计要点

- **大按钮**: 最小 48×48dp (手指点击区域)
- **大字体**: 最小 16sp (车间光线复杂)
- **高对比度**: 深色背景 + 亮色文字 (减少反光)
- **简化操作**: 每页最多 2-3 个操作按钮
- **即时反馈**: 提交后立即显示结果 (loading → success/error)
- **防误触**: 关键操作 (完工/关闭) 需二次确认
- **横屏优先**: PAD 通常横屏使用
